1. 网站

1.1 网页相关概念

1. 网站：网站(Web Site)是一个存放在网络服务器上的相关信息的集合体。它包含一个或多个网页，这些网页以一定的方式链接在一起，成为一个整体，用来描述一组完整的信息或达到某种期望的宣传效果。

整理

1. 网站（Web Site）

部署在网络服务器上的一组信息集合。它包含一个或多个网页，这些网页按某种方式链接在一起，形成一个整体，用以描述信息或达到宣传效果。

讲解

  • 直观意思：把网站想象成一本放在公共图书馆（网络服务器）里的“书”——它不是零散的废纸，而是把一张或多张页面用目录和超链接装订在一起的完整信息集合。
  • 为什么：单靠一个孤立文件往往装不下复杂业务（如首页、详情页、登录页），必须把相关页面部署在持续在线的网络服务器上，并通过链接组织成整体，外部用户才能系统地浏览并达成信息传递或宣传目的。

2. 网页

2. 网页：网页(Web pages)是网站的组成部分，由文字、图形、图像、音频、视频、动画、脚本程序、超链接等网页元素组成。通过浏览器访问。每个网页都有唯一的 URL 地址，用于定位和访问。

整理

2. 网页（Web pages）

网站的组成部分，由文字、图形、图像、声音、视频、动画、脚本、超链接等组成。每个网页都有一个唯一的 URL 地址，用于定位和访问。

讲解

  • 直观意思：如果网站是一本书，网页就是其中的“每一页”——里面能放文字、图片、音视频、动画、交互脚本和跳转链接，必须靠浏览器打开看，而且每一页都有自己的专属门牌号（唯一 URL）。
  • 为什么：互联网上存在海量文件，只有给每个网页分配唯一的 URL 定位地址，浏览器才能准确找到它，并将里面的多种媒体元素和脚本统一渲染成人类可读的界面。

3. URL

3. URL(Uniform Resource Locator，统一资源定位器，即网址)：用于描述 Internet 上资源位置和访问方式。

URL 组成：协议类型://服务器地址（端口号）/路径/文件名

顶级域名：com（公司）、net（网络机构）、org（组织机构）、edu（教育）、gov（政府部门）、mil（军事机构）和 ac（科研机构）

整理

3. URL（Uniform Resource Locator，统一资源定位器，即网址）

用来描述 Internet 上资源的位置和访问方法。

组成格式：

协议类型://服务器地址(端口号)/路径/文件名

常见顶级域名：

域名含义
com公司企业
net网络组织
org组织机构
edu教育机构
gov政府部门
mil军事组织
ac科研机构

讲解

  • 直观意思：URL 就是互联网上的“完整快递收件地址 + 派送方式”——前面说明怎么拿（协议类型），中间说明去哪栋楼哪扇门（服务器地址与端口号），后面说明去哪个文件夹拿哪份文件（路径/文件名）；而顶级域名（如 .com、.edu）相当于机构性质的分类标签。
  • 为什么：网络上资源类型多样（网页、文件传输等）、服务器成千上万、单台服务器内又有大量目录和文件。把“怎么访问”和“资源在哪”按统一格式拼成字符串，任何浏览器都能无歧义地解析定位。
  • 在实际使用中，如果采用协议默认端口（如 HTTP 默认 80、HTTPS 默认 443），URL 中的 （端口号） 通常会被省略；如果省略 /文件名，服务器通常会返回该目录下的默认首页文件。

自测要点解答

  1. 默写全称与中文：URL = Uniform Resource Locator，统一资源定位器，即网址。
  2. 按分隔符拆解 5 段格式：抓住两个关键分隔符 :// 和 /，依次写出 协议类型://服务器地址（端口号）/路径/文件名。
  3. 分类记忆 7 个顶级域名（切忌混淆 net 与 org、edu 与 ac）：
    • 商业/网络/组织：com（公司）、net（网络机构）、org（组织机构）；
    • 科教：edu（教育）、ac（科研机构）；
    • 政军：gov（政府部门）、mil（军事机构）。

4. DNS

整理

4. DNS（Domain Name System，域名系统）

管理、安排域名的分布式数据库系统，实现域名与 IP 地址的映射。

要点：

  • 一个域名只能映射到一个 IP 地址
  • 一个 IP 地址可以映射到多个域名

讲解

  • 直观意思：DNS 就是互联网的“分布式电话簿”——人记名字（域名），计算机只认电话号码（IP 地址），DNS 负责把域名翻译成 IP 地址。
  • 为什么：
    1. 为什么需要“分布式数据库”而不是单台电脑存全球域名？因为全球域名数量巨大、查询请求极高，单台服务器会瞬间崩溃，必须分层分布式管理。
    2. 为什么“一个 IP 可以映射多个域名”？因为一台物理服务器（一个公网 IP）可以托管多个不同的网站，靠不同域名区分访问哪个站点。

自测要点解答

  1. 先答本质功能：DNS（Domain Name System，域名系统）是管理、安排域名的分布式数据库系统，核心作用是实现域名 ↔ IP 地址的映射。

自测要点

  1. 3DNS：一域名→一 IP；一 IP→多域名

5. 首页（Home page）

网站的第一个网页，反映站的主题。常见首页文件名：index.html、default.html。

讲解

  • 直观意思：首页就是网站的“大门和封面”，用户只输入域名不输入具体文件名时，看到的第一张页面就是它。
  • 为什么：用户在浏览器地址栏通常只输入域名（如 www.example.com），不会手动敲完整文件名。服务器需要一个预先约定的默认入口文件名（最常见就是 index.html 或 default.html），这样才能自动把网站的第一个网页推送给用户。

自测要点解答

6. 互联网（Internet）

6. 互联网（Internet）：又称国际网络或因特网，是由全球范围内众多计算机网络通过通用协议（如 TCP/IP）相互连接而成的庞大网络基础设施。它并非单一网络，而是“网络的网络”，将分散的局域网、广域网等整合为一个逻辑上统一的全球性系统。

整理

6. Internet（互联网，又称国际网络或因特网）

由世界各地众多计算机网络通过共同协议（如 TCP/IP）互联而成的巨大网络基础设施。它不是单一网络，而是「网络的网络」。

讲解

  • 直观意思：互联网不是某一家建的一张大网，而是把全世界无数个小网（校园网、公司局域网、运营商广域网等）用同一套“交通规则”（如 TCP/IP）拼起来的超级网络底座。
  • 为什么：不同地区、不同厂商的硬件和局部网络千差万别，只有通过通用协议（如 TCP/IP）统一通信标准，才能让全球分散的局域网和广域网彼此互通，形成“网络的网络”。

7. 网站，网页，互联网三者的联系

7. 网站，网页，互联网三者的联系：

WWW 服务：最广泛的服务

互联网是全球性的网络基础设施，网站是部署在互联网上的信息集合体，而网页则是构成网站的基本单元。

整理

7. 网站、网页与 Internet 的关系

  • Internet：全球网络基础设施
  • 网站：部署在 Internet 上的信息集合
  • 网页：构成网站的基本单元

补充：WWW 服务是 Internet 上最广泛的服务。

讲解

  • 直观意思：这是一个严格的“由大到小”包含关系：互联网是“土地和公路网”，网站是建在上面的“商场”，网页是商场里的“每一间商铺”；而 WWW（万维网）是跑在这张公路网上用得最普遍的服务。
  • 为什么：明确三者层级能防止概念混用——互联网提供底层连通能力，网站提供业务级信息组织，网页承担具体页面的内容呈现，三者层层依托。

自测要点解答

  1. 定位最大底层（Internet）：先定性互联网是“全球性的网络基础设施”，是“网络的网络”，靠通用协议（如 TCP/IP）互联。
  2. 定位中间集合体（网站）：再指出网站是“部署在互联网（网络服务器）上的信息集合体”，由一个或多个网页链接而成。
  3. 定位最小基本单元（网页）：最后落到网页是“构成网站的基本单元”，由各类网页元素组成，拥有唯一 URL。
  4. 补全常考关联点：顺手带上一句材料手写重点——WWW 服务是 Internet 上最广泛的服务。

8. 浏览器/服务器交互过程

8. 浏览器/服务器交互过程：

(1)浏览器从网址中获取输入的域名；

(2)浏览器向 DNS 请求解析域名对应的 IP 地址；

(3)浏览器与该服务器建立 TCP 连接；

(4)浏览器发出 HTTP 请求，请求网页；

(5)服务器通过 HTTP 响应把网页发送给浏览器；

(6)TCP 连接释放；

(7)浏览器将首页文件进行解析，并将 Web 页显示给用户。

整理

8. 浏览器与服务器的交互过程

  1. 浏览器从输入的 URL 中取得域名
  2. 浏览器请求 DNS 解析该域名对应的 IP 地址
  3. 浏览器与服务器建立 TCP 连接
  4. 浏览器发出 HTTP 请求，请求网页
  5. 服务器通过 HTTP 响应把网页发送给浏览器
  6. TCP 连接释放
  7. 浏览器解析首页文件，并将 Web 页面显示给用户

讲解

  • 直观意思：从在地址栏敲下回车到屏幕上出现网页，一共 7 个严密衔接的动作：拆域名 → 查地址（DNS）→ 拨通电话（建 TCP）→ 要网页（HTTP 请求）→ 发网页（HTTP 响应）→ 挂电话（断 TCP）→ 画页面（浏览器解析显示）。
  • 为什么：顺序绝对不能乱，因为每一步都是下一步的前提：
    • 不先从网址取域名（1），就没法找 DNS 查 IP（2）；
    • 拿不到服务器 IP（2），就找不到目标主机去建 TCP 连接（3）；
    • HTTP 跑在可靠传输通道之上，不先建 TCP 连接（3），就发不出 HTTP 请求（4）也收不到 HTTP 响应（5）；
    • 网页数据拿完后释放 TCP 连接（6），节省服务器连接资源，再由浏览器本地解析代码并渲染给用户（7）。

自测要点解答

  1. 分三段记忆，不死背散句：
    • 找人阶段（1–2 步）：(1) 浏览器从网址中获取输入的域名 → (2) 向 DNS 请求解析域名对应的 IP 地址。
    • 通信阶段（3–6 步）：(3) 与服务器建立 TCP 连接 → (4) 发出 HTTP 请求，请求网页 → (5) 服务器通过 HTTP 响应把网页发给浏览器 → (6) TCP 连接释放。
    • 展示阶段（7 步）：(7) 浏览器将首页文件进行解析，并将 Web 页显示给用户。
  2. 锁定最易考错的 3 个顺序坑：
    • 先 DNS 解析，再 TCP 连接（没有 IP 建不了连接）；
    • 先建 TCP 连接，再发 HTTP 请求（TCP 是传输底座）；
    • 按教材顺序：先 (6) 释放 TCP 连接，再 (7) 浏览器解析并显示。

自测要点

9. HTTP 协议

9. HTTP 协议：HTTP(Hypertext Transfer Protocol)超文本传输协议，详细规定了浏览器和万维网服务器之间互相通信的规则。

整理

9. HTTP 协议

HTTP（Hypertext Transfer Protocol，超文本传输协议）详细规定了浏览器和万维网服务器之间互相通信的规则。

讲解

  • 直观意思：HTTP 就是浏览器和网站服务器对话时共同遵守的“普通话和礼仪规范”（怎么提问、怎么回答、状态怎么表示）。
  • 为什么：浏览器有很多种（Chrome、Edge、Safari 等），服务器软件也有很多种，如果没有统一的 HTTP 通信规则，浏览器发出的请求服务器就读不懂，服务器发回的数据浏览器也无法解析。

10. 静态网页和动态网页

10. 静态网页和动态网页：

静态网页：内容固定，无数据库交互，常见扩展名有.htm 或.html；

动态网页：内容不固定，按需生成，有数据库交互，常见扩展名为：.asp、.php、.jsp

整理

10. 静态网页和动态网页

类型特点常见扩展名
静态网页内容固定，无数据库交互.htm、.html
动态网页内容不固定，按需生成，有数据库交互.asp、.php、.jsp、.aspx（含 ASP.Net）

讲解

  • 直观意思：
    • 静态网页像“印好的纸质传单”：谁来看、什么时候看，内容都一模一样，背后不查数据库，文件后缀通常是 .htm 或 .html。
    • 动态网页像“现点现做的菜单”：根据你的身份或查询条件，临时去数据库取数据再拼出页面给你，后缀常见 .asp、.php、.jsp、.aspx（ASP.Net）。
  • 为什么：纯展示型页面用静态网页最省资源、速度最快；而像购物网站、查成绩、个人中心这类因人而异或实时变化的内容，不可能提前把每个人的页面都写死成 HTML 文件，必须由服务器端程序结合数据库按需生成。
  • 网页上有 GIF 动图、轮播图或视频，不等于它是动态网页！ 区分静态与动态的核心标准是内容是否固定、是否按需生成以及有无数据库交互，而不是画面“动不动”。

自测要点解答

  1. 先判本质特征：
    • 静态网页 = 内容固定 + 无数据库交互；
    • 动态网页 = 内容不固定 + 按需生成 + 有数据库交互。
  2. 再对号入座扩展名：
    • 静态网页：.htm、.html；
    • 动态网页：.asp、.php、.jsp、.aspx（ASP.Net）。
